# 產品計劃書：結構化 AI 學習系統（工程師版 Duolingo）

## 1. 產品定位

**一句話**：Duolingo 的學習結構 × AI 家教的深度，對象是工程師。

**核心洞察**：幾億人已經在跟 AI 來回學習，但那是混沌的——今天亂問 X、明天亂問 Y，沒有課綱、沒有進度、AI 不記得你學過什麼、你不知道接下來該學什麼。

**差異化對象不是其他 app，是「裸用 ChatGPT 學習」**：

| | 裸用 ChatGPT | roadmap.sh | 本產品 |
| --- | --- | --- | --- |
| 有學習路徑 | ✗ | ✓（靜態） | ✓ |
| 會教你、能追問 | ✓ | ✗ | ✓ |
| 記得你學過什麼、哪裡虛 | ✗ | ✗ | ✓ |
| 驗收你真的懂了 | ✗ | ✗ | ✓ |

**目標受眾**：像作者一樣天天用 AI 學技術、但苦於沒有系統性的工程師。作者本人即第一位用戶（正在走 Junior → Mid 的路），自用場景真實成立。

**借 Duolingo 的是骨架，不是外皮**：路徑、關卡、檢核、錯題回流留下；streak、寶石、吉祥物等遊戲化全部不要。

**系統不綁主題**：路徑只是資料，任何技術主題都能策展成技能樹——如同 Duolingo 一個 app 學多種語言。**MVP 只做第一條路徑**：React 從 Junior 到 Mid——課綱錨定 roadmap.sh 與官方文件，作者親自走完全程驗證流程有效。

**課綱分工一半一半**：常見的學習骨架（單元、節點、依賴）人工策展——品質不可賭；個人化的補強內容（針對你的弱點記錄出的練習與追打）AI 動態生成——本來就該因人而異。

## 2. 學習結構（Duolingo DNA 對應)

- **路徑（Path）**：人工策展的技能樹 JSON——單元（Unit）→ 節點（Lesson），節點間有依賴關係，未解鎖不能跳。課綱骨架人工編排（參考 roadmap.sh），AI 負責執行層與弱點補強內容，不負責生骨架——教學產品的課綱品質不可賭。
- **節點兩型**：
  - **概念型**（closure、reconciliation、event loop…）：蘇格拉底對話檢核。
  - **實作型**（寫 debounce、修 re-render bug…）：瀏覽器內寫 code 驗收。
- **檢核即課程**：不是「看完打勾」。流程是 AI 教學 → 出題 → 使用者回答 → 追問到確認真懂，掌握度才更新。每個節點附人工撰寫的考點與過關 rubric（哪些誤解算沒懂），檢核引擎以此為據，不靠 LLM 自由心證。
- **起點定位**：入門時手動勾選已會的節點，直接亮燈跳過。AI placement 測驗與 Unit checkpoint 留到多路徑之後。
- **知識會裂開**：每節點掌握度隨時間衰減，久未複習的節點在技能樹上「裂開」。裂開節點 + 歷史錯題進複習佇列——「下次打開知道要幹嘛」由此而來。

## 3. 核心循環（LangGraph.js 狀態機）

```
選節點 → 教學（對話）→ 檢核 → 掌握度更新 → 推薦下一步（新節點 or 複習）

檢核分支：
  概念型：蘇格拉底追問（答錯 → 換角度再教 → 再問）
  實作型：出題 → Sandpack 編輯器寫 code → 測試通過 + AI code review
```

**語意級弱點記錄**：檢核中暴露的具體誤解（例：「以為 useEffect cleanup 只在 unmount 執行」）以文字形式存檔，不只是分數。後續出題與複習會刻意打向這些記錄——這是「AI 記得你」的實體。

## 4. 實作題執行環境

用 **Sandpack**（CodeSandbox 開源的瀏覽器內 bundler）：

- React code 與測試都在使用者瀏覽器內執行，**不需要後端沙箱**——省掉整個容器與安全工程。
- 驗收雙軌：測試通過（客觀）+ AI code review（品質與思路）。
- 限制：Sandpack 只跑 JS/React 生態。未來非 JS 主題的路徑以概念型節點為主，實作型另議。

## 5. 技術棧（全 TypeScript）

| 層級 | 選型 |
| --- | --- |
| 框架 | Next.js (App Router) + TypeScript + Tailwind CSS |
| Agent 流程 | LangGraph.js（session 狀態機 + checkpoint） |
| LLM 介接 | Vercel AI SDK（streaming UI），Provider 透過抽象層接入、不綁定 |
| 程式碼執行 | Sandpack（瀏覽器內） |
| 資料庫 | Postgres + Drizzle ORM |
| 認證 | Auth（多用戶 + demo 帳號） |
| 部署 | Vercel 單一服務 |

單一語言、單一服務。對「前端 + AI 應用」作品集的敘事：用 TS 全端掌控 agent 流程。

## 6. UI 規劃

- **技能樹地圖**（首頁，demo 核心）：路徑視覺化——節點亮燈（已掌握）/ 裂開（衰減待複習）/ 上鎖（依賴未滿足），GSAP 動畫。面試官打開 demo 第一眼看到的畫面。
- **課程頁**：左側 AI 對話（streaming）；右側 Sandpack 編輯器（僅實作型節點出現）。
- **複習頁**：今日佇列——裂開節點 + 歷史弱點。
- **Demo 帳號**：預灌半棵亮起來的技能樹與弱點紀錄，面試官 30 秒內看懂產品。LLM 呼叫限次或預錄回放——公開網址不裸奔 LLM 成本。

## 7. MVP 範圍

**做**：

- 一條 React 路徑：2 個 Unit、約 12 個節點（概念型 + 實作型混合），每節點含考點與 rubric。
- 手動標記已會節點（起點定位）。
- 核心學習循環（教學 → 檢核 → 掌握度更新 → 下一步推薦）。
- 技能樹地圖 UI + 複習佇列。
- Demo 帳號。

**不做**（明確排除，避免範圍蔓延）：

- 多路徑 / 使用者自訂路徑。
- 社群、排行榜、成就、streak 等遊戲化。
- 行動版。
- AI 動態生成課綱骨架（弱點補強內容仍由 AI 生成，骨架不是）。
- AI placement 測驗、Unit checkpoint 總驗收。

## 8. 成功標準

1. 作者本人每週實際用它學習 ≥ 2 次（自用成立是一切的前提）。
2. 面試官打開 demo 帳號，30 秒內能理解產品在做什麼。
3. 標記起點 → 上課 → 檢核 → 技能樹亮燈的完整流程可公開網址體驗。
